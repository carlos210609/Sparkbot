# SladeGPT MCP

A single-owner MCP server that uses **ChatGPT itself as the reasoning and code-generation model**. No OpenRouter account, external model API key, or paid LLM API is required.

## How the loop works

1. ChatGPT reads the current source with read_files.
2. ChatGPT reasons about the requested task and generates code changes in the conversation.
3. start_loop writes those changes to a dedicated sladegpt/* branch and starts GitHub Actions.
4. GitHub Actions runs npm test and npm run build. It does not call an LLM.
5. ChatGPT reads status/logs and can submit fixes with apply_changes, repeating while the client and conversation continue tool calls.
6. Changes stay on a separate branch; the server does not merge into main automatically.

This is a model-in-the-loop workflow, not an unattended agent that independently runs for days without ChatGPT tool calls. Each coding iteration is generated by ChatGPT, not by a second AI service.

## MCP endpoints and OAuth

- MCP endpoint: https://ralph-loop-mcp-independent.vercel.app/mcp
- Health: /health
- Protected Resource Metadata: /.well-known/oauth-protected-resource
- OAuth Authorization Server Metadata: /.well-known/oauth-authorization-server
- OAuth client registration: /oauth/register
- OAuth authorization: /oauth/authorize
- OAuth token: /oauth/token

The server implements a minimal OAuth 2.1 authorization-code flow with PKCE S256, refresh tokens, resource metadata, and dynamic client registration. It uses a single-owner password for personal use; it is not a multi-user identity provider or an enterprise SSO service. Keep the password private and rotate it if exposed.

## MCP tools

- read_files(paths, branch?)
- start_loop(task, changes)
- apply_changes(branch, task, changes, message?)
- run_checks(branch, task)
- get_status(run_id?, branch?)
- get_logs(run_id)
- stop_loop(run_id)

File writes are allowlisted to source/tests and common project manifests. Workflow/security files and secret files cannot be changed through these tools.

## Vercel environment variables

Configure these as protected variables for Production and Preview:

- OAUTH_SIGNING_SECRET: random secret of at least 32 characters used to sign OAuth clients, codes and tokens.
- MCP_USER_PASSWORD: strong, private password used at the OAuth consent/login page.
- GITHUB_TOKEN: fine-grained GitHub token scoped to this repository, with Contents read/write and Actions read/write permissions.
- PUBLIC_BASE_URL: https://ralph-loop-mcp-independent.vercel.app

Optional variables:

- GITHUB_OWNER (default: carlos210609)
- GITHUB_REPO (default: Sparkbot)
- GITHUB_WORKFLOW_ID (default: ralph-loop.yml)

No OPENROUTER_API_KEY or external model key is needed.

After changing environment variables, redeploy and check /health. A working host should report oauthSigningSecret=true, mcpUserPassword=true, and githubToken=true. Never commit or publicly share credentials.

## Connect to ChatGPT

Use ChatGPT on the web, choose Plugins > Add custom MCP server, and enter the public HTTPS MCP endpoint. Select OAuth when asked for authentication, authorize using the MCP user password configured above, then scan/create the plugin. Custom MCP write actions depend on ChatGPT plan and workspace permissions.

## Local validation

Run npm install, npm test, and npm run build.

## Safety

The server writes only to a dedicated SladeGPT branch and runs tests/build. It does not automatically push changes to main or merge them. Review the diff and validation result before merging.
